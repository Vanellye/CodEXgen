## Purpose

StridePath connects the ERIA Root, Main, and HOME workspace through traceable
multiplication, approved propagation, and recall. It is a pathway for controlled
reconstruction—not an authority to overwrite the source.

## 1. MULTIPLY (✖)

A multiplication operation creates a separately identified derivative from an exact
source revision.

Every derivative records:

- source repository, branch, commit, and file revision;
- derivative identifier, destination, purpose, and responsible actor;
- declared changes and permission scope;
- validation results and unresolved differences;
- parent-child lineage and a recovery reference.

The source remains unchanged. A derivative is not merged or promoted into Main merely
because it exists or passes local validation.

## 2. SPREAD (ð)

Spread propagates approved, versioned principles or references across Root, Main,
HOME, and StridePath.

Propagation must preserve the originating record, identify each destination, report
partial failures, and avoid expanding the source permission scope. A trigger or
detected difference is not authorization to write.

## 3. RECALL

Recall resolves a derivative to its source revision and displays the recorded
transformation history. It must distinguish:

- original source material;
- verified facts and source quotations;
- corrections with supporting evidence;
- interpretations and hypotheses;
- unresolved or unverified claims.

Recall does not fabricate missing history. Unknown values remain unknown.

## 4. HOME identities and overrides

A Hômmmë Bõđďiê is a named workspace identity, not a person or an elevated security
principal. Its identity, source, owner, scope, and version are explicit.

An override must identify the actor, exact capability, target, reason, approval,
expiry or revocation condition, and recovery plan. Overrides are denied by default
when any required element is missing. No self-granted elevation is permitted.

## 5. Written Scripture and quotations

A quotation record preserves exact text and records its author or attributed source,
work, edition or translation, location, rights status, and verification state.
Paraphrase, commentary, and spiritual interpretation must be labeled separately.
Unverified attribution must never be presented as established fact.

## 6. TransenDance Level Rebuild

Each rebuild stage records its input revision, transformation, output revision,
diff, validation, and approval state. Rebuilds create new versions; they do not
silently rewrite the identity or history of earlier versions.

## 7. Safety and promotion gates

- No silent publication, external transmission, or destructive source overwrite.
- No branch promotion or Main integration without separate human authorization.
- No automatic permission escalation through multiplication or spread.
- Preserve append-only audit history and a tested recovery path.
- Fail closed when identity, scope, approval, evidence, or validation is missing.
- Keep all external dispatch disabled unless separately authorized for a named
  destination and purpose.

## Implementation boundary

The Android HOME screen is an informational entry point and opens the existing code
generator. It does not yet create branches, propagate files, write scripture records,
or execute overrides. Those capabilities require separately reviewed services,
tests, and authorization contracts.
