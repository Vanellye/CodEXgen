SQLite & provenance

Read-only view

Database identity

The UI displays the database path reported by ERIA. It does not open SQLite directly, migrate tables, delete records, or reconcile counts by assumption.

Database identity has not been returned by the API.
Preservation policy: retain original source rows, hashes, timestamps, provenance, and audit records. Any future import, migration, or cleanup must be a separately reviewed, transactional operation with a backup and before/after counts.

Record integrity checklist

Before any data mutation: identify the exact database file; create and verify a backup; record source and artifact counts; inspect schema and foreign keys; run integrity checks; use a transaction; verify post-operation counts and hashes. This interface currently performs none of those mutations.
